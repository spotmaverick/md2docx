- **优先级**：`--lang` > `settings.json` 记忆档位 > 系统探测 > 兜底 `en`。
  「自动」本身也是一个会被持久化的档位。

  现改为结果行 iid 即 `Result` 下标，按行取对象。**逻辑不得依赖界面文案**已成硬约束。
- `RoundButton` 绝不能用 `self._w` / `self._h` 存尺寸：它们是 `tkinter.Misc` 的内部属性

  改用 `_bw` / `_bh`。短属性名做全局替换会连带改坏 `_hover` / `_worker` 等，必须按词边界复核。
- 输出文档正文里的中文（`[图片：alt]`、链接 `文字（URL）`）**不随界面语言变化**，
  由源 Markdown 决定；`check_i18n.py` 里以 `OUTPUT_CONTENT` 白名单显式豁免（遗留 G-07）。

## Md2docs v1.6：修掉「跑 --selftest 弹出启动失败」

### 故障与根因

主人反馈截图：`Md2docs 启动失败`，堆栈落在 `gui.py` 的 `_measure()`。经核对：

- 截图里那处是 **V-13**（`RoundButton` 误用 `self._w`/`self._h`），**已修复**。
  铁证在行号：旧代码 `_measure()` 在 365 行、报错的 `configure` 在 380 行，
  且第 380 行是 `super().configure(width=self._w, height=self._h)`；
  现在 `_measure()` 在 368 行、`configure` 在 383 行、用的是 `self._bw`/`self._bh`
  （中间正好多出 3 行警告注释）。截图必然取自修复前。
- 但顺着截图去查 `Documents\Md2docs\md2docs.log`，发现**当天确实有两次真实崩溃**
  （09:53:25、10:04:28），是**另一个**故障：`UnicodeEncodeError: 'gbk' codec
  can't encode character '\u2713'`，位置 `gui.py:1774 in selftest`。

根因链：

1. 结果表状态列写的是 `✓ 成功` / `✕ 失败`（U+2713 / U+2715）。**GBK 编码不了**这两个字符。
2. `--selftest` 会把结果表**逐行打到标准输出**（这行是我在 v1.5 加的——原来 selftest
   不跑转换，所以这条路径以前走不到）。
3. 用户的普通控制台是 GBK → `print` 抛异常 → 冒到 `main` 的 `except` → `_fatal`
   弹模态框。用户看到"程序起不来"，真实原因是"一个符号打不出来"。

### 为什么我上一轮的"全部回归通过"没拦住

我的开发 shell 带着 **`PYTHONUTF8=1` + `PYTHONIOENCODING=utf-8`**
（`sys.flags.utf8_mode=1`、`sys.stdout.encoding=utf-8`），输出永远 UTF-8，
这条路径**永远不报错**。用户控制台没有这两个变量 → `utf8_mode=0`、`stdout=gbk` → 必崩。

**这是最坏的一种验证假象：开发环境全绿，真实环境起不来。**
已把"编码 / 控制台 / 代码页 / 区域设置相关验证必须在 `unset PYTHONUTF8 PYTHONIOENCODING`
后的干净环境里跑"固化为纪律（写进规格 §8.3 与 MEMORY.md）。

另：**打包产物实测不认这两个环境变量**——同一份环境里 venv 的 python 是 `utf8_mode=1`，
`dist/Md2docs.exe` 仍按 GBK 输出并崩溃。所以打包产物的输出行为必须单独确认，
不能由源码态推断。

### 改动

- `src/i18n.py`：`res.state_ok` / `res.state_fail` 由 `✓` / `✕` 改为 GB2312 符号区的
  `√` / `×`（zh: `√ 成功` / `× 失败`，en: `√ Done` / `× Failed`）；模块文档补"文案用字约束"。
- `src/app.py`：
  - 新增 `_make_output_safe()`：把 stdout/stderr `reconfigure(errors="replace")`
    （只放宽 errors、不改 encoding，中文照旧正确显示）；`_attach_console()` 里
    `open("CONOUT$", ...)` 也带 `errors="replace"`，并在末尾再调一次。
  - `_fatal(msg, headless=False) -> int`：**模态框只在图形界面模式下弹**；
    `--cli` / `--selftest` / `--diag` 只写日志与控制台；统一返回失败码。
  - `main()`：`rc` 变量贯穿，`finally` 里 `_cleanup_frozen_exit(rc)`。
  - `_cleanup_frozen_exit(code)`：退出前 `flush()`；`TerminateProcess(h, code)`

    而我们是强杀它的，不给码就等于把失败抹成 0。

- `tools/check_font_glyphs.py`（新）：取 UI 字体回退链，用 GDI `GetGlyphIndicesW`
  (`GGI_MARK_NONEXISTING_GLYPHS`) 逐字符核验词条里每个非 ASCII 字符「有字形 + GBK 可编码」。
- `tools/check_i18n.py`：把自己那句带 `✓` 的输出改成纯文本（自查工具本身也犯了同一个错）。
- `tools/shot_ui.py`：新增 `--run`，先跑一次真实转换再截图——结果表的**状态列**

- `.gitignore`：`tests/` 下凡以 `_` 开头的一律忽略（生成物），真实固件不带下划线。

### 核实过、但结论与直觉相反的一点

微软雅黑（含 YaHei UI）与 Segoe UI **确实没有** U+2713 / U+2715 的字形
（`GetGlyphIndicesW` 返回 0xFFFF），但我写了个 PrintWindow 探针逐像素比对：
**Tk 仍然把 `✓` 画出来了**（与确定缺字形的私用区字符 U+E000 的豆腐块位图明显不同），
说明系统做了字体回退。**所以界面侧当时并没有方框**，我一度准备写的"界面上显示成方框"
是错的，已在规格里改成只把"控制台崩溃"列为已验证症状。
教训：**凭"GDI 不做字体回退"的通说下结论之前先量一次**。
