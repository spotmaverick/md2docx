### 提交技巧：同名文件「改名 + 新建」的正确处理

`Md2docs.spec` 这次属于**旧 PyInstaller 配置被改名成 `Md2docs.build.spec`，
同时新建了一个同名的新规格文件**。若直接 `git add -A`，git 的改名启发式会把
两者配成一对（`RM Md2docs.spec -> Md2docs.build.spec`），暂存内容容易出错。

正确做法是分批：

1. `git add` 其余改动 + `git add Md2docs.build.spec`；
2. `git rm --cached -f Md2docs.spec` —— **只把旧路径移出索引，保留磁盘文件**
   （这一步必须带 `--cached`，否则会真的删掉刚写好的新规格文件）；
3. 先提交「迁移」，再 `git add Md2docs.spec docs/` 提交「规格」。
   两个提交叙事各自干净，内容零丢失。

## 新增环境坑：Bash 的 PATH 可能被整个清空

本机 Bash 启动会 source
`C:\Program Files\WorkBuddy\resources\app.asar.unpacked\cli\vendor\shim\shell-runtime-bash-env.sh`，
该脚本第 3 行的 `dirname` 调用失败（`dirname: command not found`），连锁导致
PATH 根本没导出 —— 于是 `cat` / `ls` / `which` / `head` 全部 command not found。

现象很像"shell 坏了"，其实是 `PATH` 为空。**迷惑点在于 `git` 仍能执行**
（不走 PATH 里那一批），所以看起来"只有部分命令坏了"。

自救：每个 Bash 调用都是新 shell，需在命令开头显式重建 PATH：

```
export PATH="/c/Users/Dell/.workbuddy/binaries/PortableGit/versions/1.2.0/mingw64/bin:/c/Users/Dell/.workbuddy/binaries/PortableGit/versions/1.2.0/usr/bin:/c/Users/Dell/.workbuddy/binaries/PortableGit/versions/1.2.0/bin:/c/Windows/System32:/c/Windows:/c/Windows/System32/Wbem"
```

纯 bash 内建（`[ -d ]` / `printf` / `for`）不受影响，可用来定位可用目录。
