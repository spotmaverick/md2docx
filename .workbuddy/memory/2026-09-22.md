# 2026-09-22 工作日志

## v1.9 语言入口改用自绘地球图标

### 需求（用户原话）
> 【语言】选项的标题，不能用文字，改为地球标识。防止其他语言用户由于看不懂当前
> 语言的提示，找不到更改语言的选项。

用户提得准。原标识是"语言 / Language"，而这段提示**本身就是用当前界面语言写的**：
用户要找的正是改语言的地方，却先被一段他读不懂的文字挡住，入口形同不存在（V-19）。
判定规则也会造成这种不一致（中文系统→中文、其余→英文），用户手切档位同样会。

### 方案与实现
- 新增 `gui.GlobeIcon`：Canvas 自绘矢量地球（外圈 + 中央经线竖椭圆 + 赤道横椭圆，
  共 3 个 oval，**零 text 图元**，**一个字符都不用**）。
  为什么不用字形：`🌐`(U+1F310) 既不在 GBK 内、也不保证字形存在
  （`check_font_glyphs.py` 会拦下放进词条的字形写法）；画椭圆不经过字体，
  天然免疫字形与编码风险，也不需要图片资源。
- 图标可点：`open_lang_dropdown()` 转发一次 ButtonPress/Release 给下拉框。
  **实测只读 `ttk.Combobox` 在控件任意位置点击都会展开**（不必点右端小箭头），
  所以没有依赖 `ttk::combobox::*` 内部命令。（探针 `tests/_probe_lang_popdown.py`）
- 档位名一律用**本名**（`中文` / `English`，`i18n.LANG_NAME`）。
- 下拉框宽度改为按最长档位**实测**（`tkfont.measure`），不再写死字符数 `width=9`
  ——写死的话，以后加了语种或改长档位名会静默裁字，那种缺陷截图都难发现。
- 删除 `lang.label` 词条（不再被任何地方引用，`check_i18n` 的闲置键检查会拦下残留）。

### 新增回归 `tools/check_lang_entry.py`
三条断言 + 一条自检：
1. 标识是 Canvas 且 ≥3 个椭圆图元，**零 text 图元**（防有人用 `create_text("🌐")` 画）；
2. 语言入口子树里**没有任何静态文字控件**（防把文字标签加回来）；
3. **真机点击链路**：点图标 → 列表展开 → 点中某一行 → 语言与窗口标题确实切换。
   两轮覆盖 zh→English、en→中文，顺带验证"英文界面下入口仍可辨认"。
4. **正控**：先造两个坏样本（带文字的 Label、`create_text` 画的假图标），两段
   采集器都必须检出，否则判"探针失效"。
另：运行期拦截 `settings.put`，**不改动主人的真实配置**（语言切换会落盘）。

### 探针有效性（注入真实缺陷验过，不是只看合成样本）
临时把文字标签加回 `langbox`、并让地球用 `create_text` 画，回归**两个缺陷都报出**
（中英各一次），rc=1；撤掉后 rc=0。**先违约再验收**才算验过探针。

### 自行踩到的缺陷 V-20：报错信息本身也可能打不出来
上面的失败注入第一次跑时，工具**缺陷检出成功、却在打印失败原因时自己抛
`UnicodeEncodeError` 中断**——因为我在失败提示里直接写了一个字面的 `🌐`。
这正是 V-14 换了个位置复发：编码问题不会因为修过一次就消失，它只是换到
"没人觉得需要保护"的地方——**错误路径**。
修复：工具入口加 `_make_output_safe()`（stdout/stderr 一律 `errors="replace"`），
提示文字用码位写法（`U+1F310`），工具回显统一经 `_ascii_safe()`。规格新增 §8.4。
