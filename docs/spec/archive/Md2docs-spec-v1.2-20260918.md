## 1. 概述

### 1.1 产品定位

面向个人与办公场景的**离线桌面工具**：把 Markdown 文档批量转换为可交付的 Word / WPS / 纯文本文件。
单文件 EXE 分发，双击即用，不安装、不联网、不依赖任何外部运行时。

### 1.2 本轮规格的核心变化

产品最初的形态是 `pywebview + WebView2 + 内置 HTTP 服务 + HTML/CSS/JS 前端`。
该方案在部分环境出现兼容性问题，根因是它把运行时可用性押在了外部组件上：

- 依赖系统安装 Edge WebView2 Runtime，缺失则界面无法启动；
- 依赖 `pythonnet` / `clr_loader`，受 .NET 运行环境与位数影响；
- 需要拉起本地 HTTP 端口，受防火墙、端口占用、安全软件干扰；
- 浏览器安全模型限制拖放文件的磁盘路径获取，导致「与源文件相同」等需求要靠
  `/api/locate` 枚举资源管理器窗口等间接手段实现，脆弱且难以稳定。

**因此确立 v1.0 的架构基线：改用纯本地的原生 Windows 桌面方案，彻底移除 Web 技术栈。**

### 1.3 范围

| 范围内 | 范围外 |
| --- | --- |
| Markdown → docx / doc / wps / txt 的本地转换 | 在线转换服务、账号体系、云端同步 |
| 原生桌面 GUI 与命令行两种使用方式 | 移动端 / macOS / Linux 适配 |
| 本机 Word / WPS 的可选调用（高质量模式） | 内嵌自研 Office 排版引擎 |
| 单文件 EXE 打包与分发 | 自动更新、安装程序 |

### 1.4 术语

| 术语 | 含义 |
| --- | --- |
| 原生模式 / 高质量模式 | 调用本机 Word 或 WPS 的 COM 接口另存为二进制 .doc / .wps |
| RTF 兼容格式 | 内置 RTF 渲染器产出的载体文件，Word / WPS / LibreOffice 均可直接打开 |
| 版心 | 页面去掉左右上下页边距后的可排版区域（A4 + 2.5cm 边距时为 16cm × 24.7cm） |
| 折叠区 | 默认收起、点击标题栏展开的次级选项区块 |

| 编号 | 需求 | 状态 |

| FR-5.1 | 开关位于折叠区标题栏右侧，启用后 `.doc` / `.wps` 走本机 Word / WPS 另存为原生二进制格式 | 已实现 |

| FR-5.5 | 原生转换失败（超时 / 异常）时自动降级为 RTF 并在结果行给出告警，不阻断其它格式 | 已实现 |
| FR-5.6 | 转换流程：先生成临时 `.docx` → 由 Office `SaveAs2` 另存为目标格式 → 清理临时文件 | 已实现 |
| FR-5.7 | COM 调用超时上限 120 秒，超时判定为失败 | 已实现 |
| FR-5.8 | 界面顶部徽标显示检测结果：「● Word / WPS 已就绪」或「○ 未检测到 Word / WPS」 | 已实现 |

> **关键约束（FR-5.2 的依据）**：WPS 安装时会劫持标准 `Word.Application` ProgID 及 CLSID
> `{000209FF-…}`，把 `LocalServer32` 指向自身 `wps.exe`。仅检测 ProgID 存在与否必然把 WPS
> 误报成 Word。正确做法是逐级解析 `HKCR\<ProgID>\CLSID` → `HKLM\SOFTWARE\Classes\CLSID\{id}\LocalServer32`
> 的实际可执行文件路径，按 `winword.exe` / 路径含 `kingsoft`·`wps`·`wps.exe` 归属分类。
> 本机实测结论：`word=False`、`wps=True`。

## 5. 排版规格

### 5.1 页面

| 项目 | DOCX | RTF（.doc / .wps 载体） |
| --- | --- | --- |
| 纸张 | A4，21.0cm × 29.7cm | PAGE_W = 11907 twips |
| 页边距 | 上下左右均为 2.5cm | 1418 twips |
| 版心宽 | 16.0cm | CONTENT_W = 9071 twips（≈16.0cm） |
| 版心高 | 24.7cm | CONTENT_H = 14004 twips |

（换算基准：1cm = 567 twips）

### 5.2 字体与字号

| 项目 | 规格 |
| --- | --- |
| 正文 | Microsoft YaHei，11pt |
| 标题 | 与正文同族，不着色，仅靠字号与字重区分 |
| 标题字号 h1–h6 | 22 / 17 / 14 / 12 / 11 / 11 pt（对齐 GitHub 的 2 / 1.5 / 1.25 / 1.1 / 1 / 1 em） |
| 等宽 | Consolas，9pt |
| RTF 字体表 | `Microsoft YaHei` / `Consolas` / `Times New Roman`（RTF 字体名仅限 ASCII） |

### 5.3 配色（GitHub 风格）

正文 `#24292F`、次要文字 `#57606A`、行内代码前景 `#1F2328`、代码块背景 `#F6F8FA`、
引用前景 `#57606A`、引用背景 `#F6F8FA`、引用竖条 `#D0D7DE`、链接 `#0969DA`、
表格边框 `#D0D7DE`、表头背景 `#F6F8FA`、表格斑马纹 `#FCFCFD`、分隔线 `#D8DEE4`。

### 5.4 版式细节

- 表格居中，列宽按 `16.0cm ÷ 列数` 均分；
- 引用块带左侧竖条与浅底纹，左右各缩进 0.2cm；
- 列表每层缩进 0.6cm；行内代码带浅底纹；
- 标题上下间距：h1/h2 段前 14pt、其余 8pt，段后统一 6pt。

## 6. 技术方案与模块结构

### 6.1 技术选型

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| 界面 | **Tkinter / ttk** | Python 标准库，操作系统原生控件，**非 Web 技术** |
| Markdown 解析 | markdown-it-py + mdit-py-plugins | CommonMark 兼容，覆盖表格 / 围栏代码 / 任意缩进嵌套列表 |
| HTML 解析 | BeautifulSoup | 承接 markdown-it 的 HTML 输出，构建语义模型 |
| DOCX 生成 | python-docx | 原生 OOXML，不依赖 Office |
| DOC / WPS 生成 | 自研 RTF 渲染器 | 纯文本格式，Word / WPS / LibreOffice 均可原生打开 |
| 原生 Office 调用 | pywin32（win32com） | 可选，仅「高质量模式」使用 |
| 拖放 | Win32 `WM_DROPFILES` | 通过 ctypes 直接调用，零第三方依赖 |
| 打包 | PyInstaller 6.x（onefile + windowed） | Tcl/Tk 运行时分发时内嵌 |

### 6.2 模块结构

```
Md2docs/
├─ Md2docs.spec            本规格说明书（需求规格唯一来源）
├─ Md2docs.build.spec      PyInstaller 打包配置
├─ assets/
│  └─ app.ico              程序图标（打包时内嵌 EXE，并随包提供窗口图标）
├─ src/
│  ├─ app.py               入口：GUI 默认 / --cli 命令行 / --selftest / --diag
│  ├─ gui.py               原生 Tkinter 界面（全部交互与自适应布局）
│  ├─ convert.py           转换调度（格式注册表、批量循环、结果汇总）
│  ├─ mdparse.py           Markdown → 中间语义模型
│  ├─ mdmodel.py           中间语义模型（Run / Block）
│  ├─ docx_writer.py       AST → .docx
│  ├─ rtf_writer.py        AST → RTF（.doc / .wps 载体）
│  ├─ txt_writer.py        AST → .txt
│  ├─ imgsrc.py            图片获取与格式/尺寸识别（三格式共用）
│  ├─ com_helper.py        Word / WPS 检测与另存（可选高质量模式）
│  └─ theme.py             排版主题（DOCX / RTF 共用）
├─ tools/
│  ├─ check_output.py      DOCX / RTF 结构自检
│  ├─ check_gui_width.py   界面回归（源码）：映射窗口下真实点击格式卡片，断言窗口宽度恒定
│  ├─ check_exe_gui.py     界面回归（产物）：对 dist/Md2docs.exe 投递真实鼠标点击，断言宽度恒定
│  ├─ grab_window.py       窗口截图（开发期核验界面用）
│  └─ make_icon.py         程序图标生成
├─ tests/  回归固件与截图工具
├─ sample/ 示例文档
└─ docs/spec/archive/      规格版本归档
```

### 6.3 数据流

```
.md 文件
  → read_text（多编码探测）
  → mdparse.parse_markdown（markdown-it → HTML → BeautifulSoup → [Block]）
  → convert.convert_file 按格式分派
      ├─ docx_writer.write_docx   → .docx
      ├─ rtf_writer.write_rtf     → .doc / .wps（默认）
      ├─ com_helper.save_as       → .doc / .wps（高质量模式，先经 .docx）
      └─ txt_writer.write_txt     → .txt
  → [Result]（逐条结果：目标路径 / 大小 / 引擎 / 告警）
```

### 6.4 中间语义模型

- `Run`：行内片段，字段 `text / bold / italic / strike / code / sup / sub / link / image / brk`
- `Block`：块级节点，`kind` 取值 `heading / para / code / quote / list / table / hr / image`，
  辅以 `level / runs / text / lang / ordered / start / items / rows / header / src / alt`

所有渲染器只消费该模型，互不感知格式细节——新增输出格式只需新增一个 writer。
